# RCA — Fundle CRM AI Prospecting: brand count stuck (+0 brands / 0 researched)

**Deployment:** fundle-sales (`https://fundlecrm.fundle.ai` → `https://fundle-sales.emergent.host`)
**Active run:** c970a68a-67df-4fc5-95a0-1cd0141fbb30
**Mode:** Diagnosis only — nothing deployed or changed.

## Summary
The prospecting engine, cron, and backend are all healthy and running. The engine produces **+0 brands** because **every Gemini LLM call through the Emergent LLM key is being rejected with `litellm.APIError: OpenAIException - Daily spend limit reached`** — exactly the same error seen in preview. No enrichment can complete, so no new brands advance and attempted prospects are marked `failed`.

## Evidence (production)

### (1) prospect_runs — latest docs
Latest 25 docs (sorted `at` desc) are **all `ok: false`**, `kind: "enrich"`, `model: "gemini-3.1-pro-preview"`, each with:
`detail: "Failed to generate chat completion: litellm.APIError: APIError: OpenAIException - Daily spend limit reached"`
Most recent `at: 2026-11-09 09:31:58`. So yes — the `detail` is the same "Daily spend limit reached" as preview. Collection holds 6,245 run docs total.

### (2) Cron POST /api/cron/prospecting
Firing and returning **2xx** — `POST /api/cron/prospecting HTTP/1.1" 200 OK` observed repeatedly (6 hits over the last 180 min window). The cron trigger itself is working; the failure is downstream inside the batch (the LLM calls), not the scheduler. The endpoint returns 200 even though the enrichment work inside it fails.

### (3) Backend logs (prospecting worker)
- Dozens of LiteLLM completion attempts to `gemini/gemini-3.1-pro-preview` and `gemini/gemini-3.5-flash` (provider=openai via emergentintegrations).
- 39 errors in the window, e.g.:
  `WARNING:core.outreach:draft failed Komaki: ... litellm.APIError: APIError: OpenAIException - Daily spend limit reached` (and V-Mart, Prestige, Poorvika Mobiles, Kekiz, etc.)
- No crashes, no 5xx on the API — the process is healthy; only the LLM provider calls fail.

### (4) prospects counts by status
- Total: **2,211** (matches "2,211 brands found")
- `enriched`: **129** (matches "129 deep researched")
- `failed`: **2,082**
Only two statuses exist (`enriched`, `failed`) — there is no `pending`/`waiting` bucket, which is why the UI shows "0 brands waiting for deep research": brands that hit the spend limit are written straight to `failed` instead of being left queued for retry.

## Root cause
The Emergent LLM key (`EMERGENT_LLM_KEY`) has hit its **daily spend limit**. Every Gemini call (enrichment `gemini-3.1-pro-preview`, `gemini-3.5-flash`, and outreach drafts) is rejected, so each prospecting batch enriches 0 brands → "+0 brands · 0 researched". This is a budget/quota condition, not an app outage.

## Suggested fixes
1. **User — raise / top up the Emergent LLM key daily budget.** Once the daily spend limit resets or the budget is increased, enrichment calls will succeed again and the brand count will resume climbing. Confirm the budget on the Emergent LLM key covers the volume the 15-min cron drives.

2. **Code (E1) — make the enrich step treat "Daily spend limit reached" as a transient/retryable error.** Today those prospects are written to `status: "failed"` (2,082 of them), so even after the budget resets they are NOT re-queued ("0 waiting for deep research"), and they will never be retried automatically. Recommend: on a spend-limit/rate error, keep the prospect in a retryable/pending state (or add a `pending` status + backfill the existing 2,082 `failed` that failed only due to spend limit) so the engine resumes those once budget is available. Reproduce/verify in an eph pod before shipping. (Not reproduced here — diagnosis only.)
