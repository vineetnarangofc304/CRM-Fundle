## Verdict
Auto-send is **working end-to-end up to the actual SMTP handshake**: cron fires, emails get auto-approved and scheduled. The failure is at the send: **outbound SMTP to smtp.office365.com:587 is failing with connection timeouts / dropped connections**, so every send attempt fails and approved emails pile up (580, of which 575 are past-due). Sending worked until ~14:16 UTC today, then connections started failing. A code behavior amplifies the outage: one failed send aborts the whole batch for that cron run.

This is NOT caused by caps (hourly quota is fully open — 0 sent in the last hour) and NOT by cron/auto-approve (both running).

## Root cause (why nothing sends)
1. PRIMARY (and only) sending inbox = Office365 SMTP `smtp.office365.com:587`. Live connections are timing out / being dropped (connection-level, not auth). Started ~14:16 UTC 11-12.
2. Code amplifier in `core/outreach.py::_send_one`: on ANY failed send it sets `sender["remaining"] = 0`. With a single inbox, the batch `while any(s["remaining"]>0)` loop ends immediately → each cron run gives up after exactly ONE failed attempt (matches outreach_last failed:1, sent:0, and send_attempts all =1). The failed email is pushed to `scheduled_at = now+1h` and status back to `approved`. Net throughput ≈ 0 while SMTP is flaky.
3. Caps are not the blocker: hourly_cap=25 rolling, 0 sent last hour → remaining=25, per_run=ceil(25/4)=7 available this run.

## Suggested fixes
### A) User / Office365 admin (primary — external)
The Office365 mailbox `Abhinav.Khanna@fundle.ai` cannot complete SMTP connections on 587. Investigate on the Microsoft 365 side:
- Confirm Authenticated SMTP (SMTP AUTH) is still enabled for this mailbox/tenant and the password/app-password is still valid (MFA may require an app password).
- Check for Microsoft throttling / a temporary send block triggered after the earlier burst (200 sent in ~24h) — M365 enforces connection and rate limits.
- Verify outbound egress from the app to smtp.office365.com:587 is not being intermittently blocked.
- More reliable long term: switch Outlook sending from SMTP to "Sign in with Microsoft" (Graph API `Mail.Send`) — the code already supports Graph (`_graph_send`), which avoids SMTP AUTH/port issues entirely.

### B) Code (E1 — resilience; redeploy)
- `_send_one`: do NOT zero `sender["remaining"]` on a transient connection error (timeout / "Connection lost"). Only disable/stop the inbox on hard auth rejections (already detected via "rejected the mailbox"/"SMTP sending turned off"). On transient errors, continue the batch (optionally skip that recipient) so other queued emails are still attempted.
- Make `is_connected()` (or a preflight) verify live connectivity before entering the send loop, so health is visible instead of silently failing per-message.
- Cleanup: `daily_cap` (200) in settings is not enforced anywhere (only `hourly_cap` 25 rolling is) — align the UI/label or wire it up to avoid confusion.
